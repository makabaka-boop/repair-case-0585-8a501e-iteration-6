# 卫星遥测缺口修复（Telemetry Gap Repair）

卫星过站后会出现一段长度为 `n` 的连续遥测整体丢失。本服务用两种修复源
A、B，以首尾相接的半开区间 `[start, end)` 覆盖整个缺口 `[0, n)`，求最小
成本的完整分段方案。

## 代价定义

- 缺口位置编号为 `0 … n-1`。位置 `k` 上使用源 A / B 的逐位置代价分别为
  `costs[k].a`、`costs[k].b`，取值均为 `0 … 1_000_000` 的整数。
- 两种源各有一次性的**段启用费** `fee_a`、`fee_b`（同样为
  `0 … 1_000_000` 的整数）。**每启用一段就收一次**：即使相邻两段使用同一
  种源，后一段仍要重新支付启用费。
- 一段 `[i, j)` 只能选择一种源 `s`，其成本为

  ```
  fee[s] + Σ costs[k].s,  k ∈ [i, j)
  ```

- 方案由若干 `[start, end)` 段组成，满足
  `0 = start₀ < end₀ = start₁ < … < end_m = n`，每段长度
  `1 ≤ end - start ≤ L`。方案总成本是各段成本之和。

## 输入 / 输出

`POST /solve`，普通 JSON：

```json
{
  "n": 5,
  "L": 3,
  "fee_a": 10,
  "fee_b": 3,
  "costs": [
    {"a": 1, "b": 4},
    {"a": 2, "b": 3},
    {"a": 5, "b": 1},
    {"a": 1, "b": 4},
    {"a": 2, "b": 2}
  ],
  "objective": "default"
}
```

`objective` 为可选项，可省略，或取：

- `"default"`（默认）：最小成本后，继续按默认的段数、末段起点、末段来源顺序裁决；
- `"continuity"`：先保证最低总成本，再依次最小化相邻段的修复源切换次数、总段数、末段起点、末段来源。首段不计切换；这些键完全并列时，沿用前缀自身的同序裁决。

非法 `objective` 返回 **HTTP 422**，响应体只含标准 `detail`。

### 段数上限 `max_segments`（可选）

人工值班表一次最多接收固定数量的修复段。可在请求中提供整数
`max_segments`（取值 `1 … 8`），要求方案**至多**使用该数量的段：

```json
"max_segments": 4
```

- 省略该字段或传 `null`：完全没有段数限制，响应与旧版本逐字段一致（含
  维护窗口、两种 objective 的全部既有裁决）；
- 提供时，已用段数进入优化状态：所有递推按“恰好使用 c 段”分层，仅在段数
  不超过上限的方案集合中求最低成本，再沿用既有的同价顺序裁决
  （default 的段数键 / continuity 的切换数、段数键等）；
- `certainty` 只根据**满足上限的全部最低成本方案**重新计算，绝不复用无
  上限的逐点结论——上限可能改变最低成本本身，此时来源并集也随之收窄；
- 上限恰好卡住最优时，求解器返回约束内的真正最低成本方案，而不是无约束
  最优解的裁剪结果。

两种明确的无解原因（均为 **HTTP 409**、响应体只含 `detail`，不输出任何
半截修复计划、局部 `cost`/`segments`/`certainty`）：

```json
{"detail": "MAX_SEGMENTS_EXCEEDED"}
```

表示维护窗口 / `L` 下存在合法完整覆盖，但覆盖整个缺口所需的最少段数已经
严格超过 `max_segments`（成本无关的可达性递推先给出最少段数，因此不会与
普通无解混淆）；而

```json
{"detail": "NO_FEASIBLE_REPAIR"}
```

仍表示维护窗口本身使缺口无法被任何合法分段覆盖（与上限无关，把上限放宽
到 8 仍是同一结论）。

分层递推的代价是 O(`max_segments`·(n+m)) 时间、O(`max_segments`·n) 空间；
`max_segments ≤ 8`，在 `n=200000` 下仍是线性量级。取值越界（`0`、`9`、
负数）、错误类型（`"2"`、`1.5`、布尔）或与其它字段重复出现的同名 JSON
键，均按统一严格协议返回可定位的 **HTTP 422**（位置 `body.max_segments`），
不进入调度。

请求协议采用严格 JSON 校验：

- 顶层、每个 `costs` 元素、`unavailable`、每个维护窗口对象以及
  `executed_prefix` 的每个段对象都必须只声明本文档列出的字段；拼写错误
  （如 `objectve`、`unavailble`、`stat`）或额外扩展字段（包括试图在已执行
  段上私加 `cost` / `fee`）均返回 422，不会按缺省约束继续调度；
- 同一 JSON 对象不得重复提供键。即使重复的是 `objective`、`unavailable`、
  `max_segments`、`costs.a/b`、`unavailable.A/B` 或窗口的 `start/end`，也
  返回可定位的 422，绝不采用“后值覆盖前值”的语义；
- 所有校验失败只包含标准 `detail` 负载，不包含任何局部 `cost`、`segments`
  或 `certainty`。

### 已执行前缀 `executed_prefix`（可选）

补片可能已在前几个维护窗口里按既定计划执行。新窗口只需保留已执行的部分、
重算尚未修复的缺口。可在请求中按顺序提供已执行段（半开区间 + 来源）：

```json
"executed_prefix": [
  {"start": 0, "end": 2, "source": "A"},
  {"start": 2, "end": 5, "source": "B"}
]
```

服务先做**前置校验**，任一不满足都返回可定位的 **HTTP 422**（`loc` 根为
`body.executed_prefix`，并带段下标），不进入调度：

- 各段必须**按顺序、无空隙、无重叠**地恰好覆盖 `[0, p)`：首段 `start` 必须
  为 `0`，后一段的 `start` 必须等于前一段的 `end`（因此不允许“只从中间某
  位置开始”的前缀）；
- 每段仍满足 `1 ≤ end - start ≤ L` 且 `end ≤ n`；
- 每段使用的来源必须在该段的全部位置可用，即已执行段不得与本次请求里该来源
  的任一维护窗口相交（半开端点：`end` 处立即可用）；
- 段对象只允许 `start` / `end` / `source` 三个字段：**没有费用字段**。前缀
  费用一律由服务按当前 `fee_a` / `fee_b` 与 `costs` 重新逐段累加，调用方
  填写的任何费用都不会被采信（多填字段本身就是 422）。

校验通过后，求解器以该固定前缀为条件优化剩余区间 `[p, n)`：

- `p = 0`：省略字段、传 `null` 或传空列表 `[]` 均等价，响应与旧版本逐字段
  一致（两种 objective、维护窗口、段数上限的全部既有裁决都不变）；
- `p = n`：前缀本身已是唯一完整方案，直接按现行费率重算总成本并返回该方案；
  每个位置的 `certainty` 强制为执行段的来源（前缀段内不存在其他最优延伸）；
- 剩余区间被等价地视为一个从位置 `p` 开始的新缺口（逐位置代价前缀和与可用
  性表整体平移 `p`），再把优化出的新段平移回原坐标，与已执行段拼接返回；
- `objective="continuity"` 时，从前缀**末段来源**到首个新段的来源切换照常
  计一次切换；前缀内部的边界是既定历史，不重新参与最小化；
- 提供 `max_segments = M` 时，**先扣除已执行段数** `c0`：剩余部分至多使用
  `M - c0` 段（`p < n` 时至少还需 1 段，故 `c0 ≥ M` 直接不可行）；
- `certainty` 只在**延伸该固定前缀的全部最低成本完整方案**中判定：已执行
  位置被强制为执行来源，剩余位置取后缀最优方案集合的来源并集（前缀成本是
  常数，不改变后缀的最优性判据）；两种 objective 的标签仍相同。

确定的无解结果（同样不返回任何半截计划）：

- 后缀区间本身无法被合法分段完整覆盖（新窗口把剩余某些位置对两源都封锁）：
  **HTTP 409** `{"detail": "NO_FEASIBLE_REPAIR"}`；
- 存在合法延伸但最少需要的段数严格超过 `M - c0`（含 `c0 ≥ M` 且尚有未修复
  位置）：**HTTP 409** `{"detail": "MAX_SEGMENTS_EXCEEDED"}`。

  后缀可达性先于段数预算判定，因此“后缀不可覆盖”不会被误报成段数超限。

### 维护窗口 `unavailable`（可选）

A、B 两种源可能在部分位置临时维护。可在请求中为每种源分别传入按位置计的
半开区间列表：

```json
"unavailable": {
  "A": [{"start": 2, "end": 4}],
  "B": [{"start": 0, "end": 1}, {"start": 6, "end": 9}]
}
```

- 每个区间 `[start, end)` 必须满足 `0 ≤ start < end ≤ n`；
- 同一来源的区间必须**严格递增**，不得重叠，也不得相接（前一个的 `end`
  必须严格小于后一个的 `start`；半开语义：`end` 处位置立即可用）；
- 两种源的窗口互不影响（允许同时维护、跨源区间重叠或端点相接）；
- 区间只约束使用该来源的完整分段：任何使用源 `s` 的段都不得与源 `s` 的
  任一窗口相交（即段内每个位置都必须可用）。

违反上述任一规则（含错误类型、未知来源名）返回 **HTTP 422**，响应体只含
`detail`。若维护窗口导致缺口无法被任何合法分段完整覆盖，返回
**HTTP 409** 且响应体仅为

```json
{"detail": "NO_FEASIBLE_REPAIR"}
```

不泄露任何局部 `cost`、`segments` 或 `certainty`。

可用性直接进入递推：合法前驱范围为
`[max(j-L, 该源 j 之前最后一个不可用位置+1), j-1]`，后缀递推的后继上限
为 `min(j+L, 该源 j 起第一个不可用位置)`，末段来源状态与 certainty 合并
同样按来源可用性裁剪。求解器不会先求无约束最优解再事后裁剪，也不展开
位置与窗口的笛卡尔积；额外开销为 O(n+m) 时间、O(n) 空间（`m` 为窗口
总数）。省略 `unavailable`、传 `null`、或两侧均为空列表时，响应与旧版
本逐字段一致。

返回：

```json
{
  "cost": 20,
  "segments": [
    {"start": 0, "end": 2, "source": "B"},
    {"start": 2, "end": 5, "source": "B"}
  ],
  "certainty": ["B_ONLY", "B_ONLY", "B_ONLY", "B_ONLY", "B_ONLY"]
}
```

`certainty` 长度为 `n`，逐位置（0 … n-1）报告该位置在**全部最低总成本方案**
中的来源确定性：

- `A_ONLY`：覆盖该位置的最优段只可能用 A；
- `B_ONLY`：只可能用 B；
- `EITHER`：存在两条总成本均为全局最小值的合法分段链，其中一条以 A 段
  覆盖该位置，另一条以 B 段覆盖它。

判定只依赖“成本是否等于全局最小值”，与段数、切换次数、末段起点 / 来源等
次级裁决无关——它们只是在最优方案集合中挑出一个，不会缩小集合。因此
`default`、省略 `objective` 与 `continuity` 对同一请求返回**完全相同**的
`certainty`；`cost`、`segments` 仍按各自 objective 的既有规则裁决，旧版本
的这两个字段逐值不变。输入校验失败时仍只返回含 `detail` 的 422，不泄露任何
局部 certainty。

提供 `max_segments` 时，“全局最小值”特指**满足段数上限**的方案集合的最小
成本：标签只统计段数不超过上限的最优方案，两种 objective 仍返回相同标签；
若上限改变了最低成本，标签可以与无上限响应不同（例如无上限时中间位置为
`EITHER`、上限内只有 A 能成为最优，则该位置变为 `A_ONLY`）。

约束：`1 ≤ n ≤ 200000`、`1 ≤ L ≤ 4096`、`max_segments` 缺省或为
`1 … 8` 的整数；所有代价 / 启用费为 `0 … 1_000_000` 的整数。`len(costs)`
必须等于 `n`。任何长度不符、数值越界、非法 `L`、非法 `max_segments`、非法
`executed_prefix`（未首尾相接、长度越界、与维护窗口冲突等）或类型错误都返回
**HTTP 422**，响应体只含标准校验错误 `detail`，不返回成本，也不返回任何局部
分段。

## 递推与唯一方案

令 `dp[j]` 为覆盖 `[0, j)` 的最优方案。对每个终点 `j`，在源
`s ∈ {A, B}` 与起点 `i ∈ [j-L, j-1]`（且 `i ≥ 0`）上取候选

```
(dp[i].成本 + fee[s] + Σ_{k=i}^{j-1} costs[k].s,
 dp[i].段数 + 1, i, s)
```

候选严格按四元组的字典序比较，依次为：

1. 累计成本（最小）
2. 段数（最少）
3. 前驱下标 `i`（最小）
4. 源（A < B）

因此递推唯一确定最优方案，不含任何随机或实现相关的平局处理。

### continuity 模式

`objective="continuity"` 在所有最低成本方案之间依次比较：

1. 相邻段来源切换次数（首段不计）；
2. 段数；
3. 末段起点；
4. 末段来源（A < B）；
5. 若仍并列，递归沿用前缀方案的同一套顺序。

例如 `n=3, L=1, fee_a=fee_b=0, costs=[(0,0),(1,0),(0,1)]` 时，最低成本为 0：
默认模式得到 `ABA`；continuity 模式在 `ABA`（两次切换）与 `BBA`（一次切换）之间选择
`BBA`。

## 算法

对固定源 `s`，候选值可改写为

```
(dp[i].成本 - prefix_s[i]) + prefix_s[j] + fee[s]
```

其中 `prefix_s[j]` 是源 `s` 在 `[0, j)` 上的逐位置代价前缀和；与 `i`
相关的部分只有 `dp[i].成本 - prefix_s[i]`，而可行起点 `i` 恰好构成滑动
窗口 `[j-L, j-1]`。

实现为每个源维护一个**单调双端队列**，队列元素的键为

```
(dp[i].成本 - prefix_s[i], dp[i].段数, i)
```

- 窗口左沿滑出的队首直接淘汰；
- 入队时从队尾弹出键严格更大的元素（键相同则保留更小下标，以满足“前驱
  下标更小优先”的平局规则）。

每个下标每源入队 / 出队至多一次，整体复杂度 **O(n) 时间、O(n) 空间**
（优于 O(n log n) 要求），不逐终点枚举 `L` 个起点，也不调用任何优化求解
器。结果由前驱指针回溯重建，每段都可按上述递推独立重算并精确复现报告的
最优成本。

`continuity` 模式为“末段来源 A / B”分别保存前缀状态。每个新来源只从对应
末段来源的状态窗口转移；另外使用无来源哨兵仅生成首段，首段不增加切换数。
哨兵不会写入 A / B 状态窗口，回溯也只引用 continuity 自己的状态，因此不会
事后改写默认模式中已淘汰的前缀。每个 `(前一来源, 新来源)` 组合维护一个滑动
窗口；窗口键在最低成本外包含切换数和段数，跨窗口比较再使用末段起点、末段
来源和前缀完整裁决键。默认模式仍走独立的原有递推，比较键与结果保持不变。
两种模式在 `n=200000, L=4096` 下均为 **O(n) 时间、O(n) 空间**。

### 段数上限的分层递推

提供 `max_segments = M` 时，已用段数成为状态维度。令 `f[c][j]` 为恰好使用
`c` 段覆盖 `[0, j)` 的最低成本（`f[0][0]=0`，其余初始不可达），逐层做与无
上限递推同构的滑动窗口最小值：第 `c` 层只从第 `c-1` 层的终点接一段，第 1 层
只接受空前缀哨兵，前驱终点在扫描到 `j` 时惰性激活（`j-1`），保证一层不会
读到自己。default 目标在层内按 `(成本, 前驱, 来源)` 裁决、层间按
`(成本, 层号)` 选最终方案；continuity 目标在外层套同样的分层，窗口键含切换
数并保留完整递归裁决键，最终按 `(成本, 切换数, 层号, 末段起点, 末段来源)`
裁决。

可行性先由一趟**忽略成本**的可达性递推决定：`need[j]` 是覆盖 `[0, j)` 所需
的最少段数（每源一个 FIFO 双端队列，等值前驱不互相支配，只在左沿过期）。
`need[n]` 不存在即维护窗口导致无解（409 `NO_FEASIBLE_REPAIR`）；
`need[n] > M` 才是段数超限（409 `MAX_SEGMENTS_EXCEEDED`）。不能在等于 `M`
时提前剪枝：`L=1` 时终点 `j` 永远恰需 `j` 段，中途的高段数终点是后面方案的
必经前驱。

上限内的 certainty 同样做带段数维度的前缀 / 后缀切分。源 `s` 的段
`[i, j)` 接在“恰好 c 段前缀”之后时，能进入某个上限内最优方案当且仅当

```
f[c][i] - P_s[i] + P_s[j] + fee[s] + g[M-c][j] == F[M][n]
```

其中 `g[b][j]` 是以**至多** `b` 段覆盖 `[j, n)` 的最低成本（精确段数行反向
扫描后再做预算前缀最小值），`F[M][n]` 是上限内全局最优。每组 `(c, s)` 各用
一个与无上限 certainty 同构的单调双端队列取窗口最小起点，写入按源区分的差
分数组；标签只由满足该等式的段合并而来，因此严格限定在上限内最优集合上。

## certainty 的计算

令 `f[i]` 为覆盖 `[0, i)` 的最小成本（不区分末段来源），`g[j]` 为覆盖
`[j, n)` 的最小成本。一段源 `s` 的 `[i, j)` 能出现在某条全局最优方案中，
当且仅当

```
f[i] + fee[s] + P_s[j] - P_s[i] + g[j] == f[n]
```

其中 `P_s` 是源 `s` 的逐位置代价前缀和。充分性来自把**任意**最优 `[0,i)`
前缀、该段、**任意**最优 `[j,n)` 后缀直接拼接：它合法且总成本恰为
`f[n]`；必要性则因任何含此段的方案成本都不低于该和、而全局最小为 `f[n]`。

对固定终点 `j` 与源 `s`，可行起点窗口 `[max(0,j-L), j-1]` 上只需判断
`h_s(i) = f[i] - P_s[i]` 的窗口最小值是否等于目标值
`f[n] - g[j] - fee[s] - P_s[j]`。用与主递推同构的单调双端队列维护
`h_s(i)`（等值保留更小下标），取到最小值的最小起点 `i_min` 的单段
`[i_min, j)` 已经覆盖所有最优起点区间 `[i, j)` 的并集 `[i_min, j)`。将
每个 `(j, s)` 的这一区间写入按源区分的差分数组，最后线性扫描即可得到逐
位置的来源并集。

### 固定前缀如何进入既有递推

给定覆盖 `[0, p)` 的合法已执行前缀，剩余问题 `[p, n)` 与一个从 `0` 开始的
新缺口完全同构：把源 `s` 的逐位置前缀和整体减去 `P_s[p]`（递推只读差值，
平移不改变任何候选成本），把可用性表的位置整体减去 `p`（`p` 之前的封锁点
钳为 `-1` / `0`，正好对应“从后缀起点向前没有封锁”）。后缀解出的新段整体
加回 `p` 即与前缀拼接，总成本 = 按现行费率重算的前缀成本 + 后缀最优成本。

- 默认目标：后缀走原有滑动窗口递推，不受前缀来源影响；
- continuity：后缀起点 0 被播种为一个真实的“末段来源 = 前缀末段来源”状态
  （零相对成本、零相对切换、零相对段数），无来源哨兵不再出现，因此首个新段
  与前缀末段异源时计一次切换，同源时不计；
- 段数上限：后缀分层递推的预算改为 `M - c0`，第 1 层从该真实状态接一段，
  可行性仍由成本无关的可达性递推先行判定；
- certainty：后缀走原有的前缀 / 后缀切分（带或不带段数维度），前缀位置直接
  强制为执行来源。`p = n` 时没有后缀，前缀即唯一最优完整方案。

`p = 0` 时所有计算仍走原有代码路径，旧响应逐项不变；额外开销仅为 O(n) 的
一次表平移。

- 不枚举任何完整分段（每个 `(j, s)` 只贡献至多一个区间，总共 O(n) 个），
  也不只重放胜出前驱——那会漏掉其他同样最优的前驱；
- `f` 与 `g` 各是一趟滑动窗口最小值 DP（后缀 DP 的窗口沿下标递减方向滑
  动，队首淘汰 `k > j+L` 的后继），含 certainty 合并全程 **O(n) 时间、
  O(n) 空间**，`n=200000, L=4096` 下与原求解器同量级。

## 运行

要求 Python 3.12（或用 Docker）。

本地：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Docker Compose：

```bash
docker compose up --build          # 宿主端口默认 8000
API_PORT=9000 docker compose up    # 用 API_PORT 覆盖宿主端口
```

容器以非 root 用户 `appuser`（uid 10001）运行。

## 一次性验收

`verify` 是一次性服务，运行 pytest 后退出：

```bash
docker compose run --rm verify
```

## 测试

`tests/test_solver.py` 包含：

- `n ≤ 8` 的小规模预言机会枚举全部合法切分与 A/B 来源，并分别核对
  `default`、`continuity` 的完整递归裁决；
- 独立的 certainty 预言机枚举**全部**合法分段及来源、只保留总成本等于
  全局最小值的方案，核对逐位置来源并集；`n=3、L=2、费用全 0、
  costs=[(0,5),(0,0),(5,0)]` 锁定为 `[A_ONLY, EITHER, B_ONLY]`，两个
  objective 完全一致；另有 O(nL) 的朴素前缀 / 后缀切分预言机在
  `n=200000, L=3` 及随机中小规模上对拍；
- `n = 3, L = 1`、费用全零、`costs=[(0,0),(1,0),(0,1)]` 锁定默认 `ABA`、
  continuity `BBA`；`cost`、`segments` 保持旧版本逐项回归；
- 随机小规模 / 中规模对拍，以及 `n = 200000`、`L = 4096` 的两种模式最大
  规模用例（含 certainty 的 O(n) 时限）；continuity 与独立的惰性删除堆
  参考实现逐段比对，并校验时限；
- `n = 200000`、`L = 3` 时默认模式与朴素 O(nL) 递推对拍；
- 对每个返回方案按代价定义直接重放，断言恰好等于返回成本，且分段首尾相
  接、长度合法；
- 省略 `objective` 与显式 `"default"` 的 `cost`、`segments` 完全一致；
- 长度不符、越界、非法 `L`、非法 `objective`、错误类型、缺字段、未声明字段
  及 JSON 对象内重复键均返回 422 且响应体只含标准 `detail`。
- `tests/test_strict_protocol.py` 在顶层、`costs`、`unavailable` 与窗口层分别
  注入拼写错误、额外键与重复键，并使用“缺省选择 A、正确窗口强制首位置选择
  B”的对照数据，验证非法请求不会回退为无约束方案，合法旧请求、省略
  `objective`、`unavailable` 为 `null`/空对象/空列表及两种目标模式的结果不变。

`tests/test_unavailable.py` 覆盖维护窗口：

- `n ≤ 5` 时对**全部**来源不可用子集组合（每位置 4 种状态）枚举全部合法
  分段与来源，交叉核对两种 objective 的完整递归裁决、逐位置 certainty
  与不可行判定；另有随机窗口与独立 O(nL) 朴素前缀/后缀切分预言机对拍；
- 半开窗口端点（`start` 处不可用、`end` 处立即可用、`end == n` 合法）、
  单源全程可用、两源同时失效、窗口强制切分等锁定用例；
- 相接 / 重叠 / 乱序 / 越界 / 错误类型 / 未知来源名的窗口均返回仅含
  `detail` 的 422；不可行时返回仅含 `{"detail": "NO_FEASIBLE_REPAIR"}`
  的 409；
- 省略、`null`、空列表与旧请求逐字段回归；`n = 200000` 含窗口的最大规模
  用例校验 O(n) 时限与分段合法性。

`tests/test_max_segments.py` 覆盖段数上限 `max_segments`：

- 独立预言机对短缺口（`n ≤ 5`）枚举**全部合法分段与 A/B 来源**、全部维护
  窗口子集组合（每位置 4 种状态）及 `max_segments = 1 … 8`，只保留段数满足
  上限的方案，交叉核对两种 objective 的完整递归裁决、逐位置 certainty 与两种
  无解原因；另含上千条随机短实例与窗口对拍；
- 上限恰好卡住最优（无上限最优段数超过上限、成本被迫升高，certainty 随之
  收窄）、同价方案确定性裁决随上限变化、维护窗口强制切分、两种 objective、
  省略 / `null` / 宽松上限与旧响应逐字段回归（含窗口）；
- 无合法覆盖与“合法覆盖存在但最少段数超限”分别返回
  `NO_FEASIBLE_REPAIR` 与 `MAX_SEGMENTS_EXCEEDED` 的 409，响应体只含
  `detail`，无半截计划；`0`、`9`、负数、字符串、浮点、布尔等非法
  `max_segments` 及重复 JSON 键均返回定位到 `body.max_segments` 的 422；
- OpenAPI 将该字段记录为可选、可空、`1 … 8` 的整数；最大规模
  （`n = 200000`）校验分层递推的时限与内存。

`tests/test_executed_prefix.py` 覆盖可选已执行前缀 `executed_prefix`：

- 独立预言机对短缺口枚举**全部合法完整分段与 A/B 来源**，只保留前 `c0` 段与
  已执行前缀逐段相等的方案，再分别核对两种 objective 的完整递归裁决、逐位置
  certainty、段数上限（扣除已执行段数后）与两种无解原因；穷举覆盖
  `p = 0 … n` 的每个边界、每个 `L`、每对来源维护窗口子集与 `max_segments =
  1 … 8`，另含两千条随机短实例与逐方案成本重放；
- `p = 0`（省略 / `null` / 空列表）与旧响应逐字段回归，`p = n` 返回按现行
  费率重算的唯一方案且全部位置强制为执行来源；
- continuity 验证前缀末段到首个新段的来源切换计数，前缀内部边界不重新最小
  化；certainty 验证前缀位置强制、后缀位置取后缀最优集合；
- 空隙 / 重叠 / 首段非零 / 零长 / 超长 / 越界 / 非法来源 / 错误类型 / 调用方
  私加 `cost` 字段 / 新窗口与已执行段相交均返回 `loc` 定位到
  `body.executed_prefix[下标]` 的 422；`null`/空列表与省略等价；重复 JSON
  键同样 422；
- 后缀不可覆盖与“剩余段数超预算”分别返回 `NO_FEASIBLE_REPAIR` 与

  （`n = 200000`）验证平移后递推仍为线性时限。
